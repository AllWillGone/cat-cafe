# Agent Rules

本项目是猫咖管理系统：后端 FastAPI + SQLAlchemy + MySQL，包含 Android 客户端。修改代码或项目文档前必须以仓库真实文件为准，不凭记忆补全。

## 权威信息来源

- 数据库结构以 `database/init.sql` 为准；`models.py` 只能映射结构，不负责建表，禁止新增 `create_all()`。
- 后端现状以 `backend/CLAUDE.md`、`docs/开发日志.md` 和实际代码共同确认；根目录 `CLAUDE.md` 可能包含旧进度。
- 接口实现以 `backend/routers/`、`backend/schemas.py`、`backend/models.py` 为准。发现文档和代码不一致时，先指出差异，再决定是否同步。
- Android 端状态以实际目录结构、源码和开发日志为准；不存在或无法确认的模块、页面、接口调用、测试结果不得写成已完成。

## 修改前必做

- 先读相关模块代码、Schema、Model、路由和开发日志，不确定的字段、状态码、权限规则不得猜。
- 任何涉及数据库字段、表关系、状态枚举、接口路径、响应结构的改动，必须同时检查 `database/init.sql`、`backend/models.py`、`backend/schemas.py`、对应 router 和文档。
- 修改项目文档前，必须先确认文档要描述的内容来自真实来源，不允许按常见项目经验补写。
- 不要修改或提交 `.env`、`.venv/`、本地 IDE 配置、数据库密码等敏感或本机文件。

## 文档修改专用流程

修改四份项目文档前，必须先读取并交叉核对以下来源：

- `database/init.sql`：数据库表、字段、约束、初始数据。
- `backend/models.py`：ORM 映射关系。
- `backend/schemas.py`：请求和响应结构。
- `backend/routers/`：接口路径、权限、业务逻辑、状态码。
- `backend/CLAUDE.md`、`docs/开发日志.md`：已完成工作、历史记录和已知问题。
- 实际目录结构：确认前端、Android 端、测试、部署脚本等是否真实存在。

写入文档前必须先和用户确认：

- 读取和核对完成后，先列出拟修改的文档、主要改动点、依据文件、发现的不一致和无法确认内容。
- 在用户明确确认前，只允许阅读、分析、列差异和提出修改方案，不得写入或改动任何项目文档。
- 用户确认后，按确认范围修改文档；如修改过程中发现新的不一致或超出确认范围的内容，必须再次暂停并向用户确认。

写文档时必须遵守：

- 文档中所有功能、接口、字段、权限、状态流转必须能在代码、数据库脚本或开发日志中找到依据。
- 找不到依据的内容只能写为“未实现”“待完善”“未在当前代码中确认”，不能写成已完成。
- 发现旧文档和代码不一致时，先列出差异，再按代码和开发日志修正文档。
- 不主动新增系统设计、接口、数据库字段、测试结果、部署流程或运行效果。
- 不把计划、设想、常见做法、课程项目模板内容写成当前项目事实。
- 对于无法确认的内容，保留谨慎表述，并在收尾说明中列出。

## 改动边界

- 每次任务只修改与需求直接相关的文件，禁止顺手重构、统一风格、批量改名或移动目录。
- 禁止为了“看起来更完整”新增未被需求要求的接口、字段、表、依赖、架构层或文档章节。
- 不确定需求时先提问；不确定代码行为时先查代码或运行验证，不得自行脑补。
- 修改完成后必须说明：改动文件、内容依据、发现的不一致、验证命令、未验证风险。

## 后端约束

- 保持现有命名：数据库字段使用 camelCase，表名沿用 `user/catinformation/product/orders/comment/likes`，接口路径沿用现有 `/api/...` 风格。
- 认证和权限必须复用 `auth.py` 的 `get_current_user` / `get_current_admin`，不要相信客户端传入的 `userId` 或 `userType`。
- 订单必须尊重 `batchNo` 聚合、库存扣减/恢复、订单状态 `0-4`；商品下架使用 `status=0`，不要为历史订单随意硬删商品。
- 评论 `targetType + targetId`、点赞 `likeType + objectId` 是软引用；修改时必须保留目标存在性校验。
- 金额字段使用 `Decimal` / `Numeric(10, 2)`，不要改成 float。

## 验证与收尾

- 后端改动后至少运行语法检查：`python -m compileall backend`；能启动时再用 `uvicorn main:app --reload` 和 `/docs` 手测相关接口。
- 修改接口、字段、状态码、权限或已知行为后，同步更新 `docs/开发日志.md` 和必要的 `CLAUDE.md`。
- 只修改文档时，也要说明是否实际读取了代码、数据库脚本和开发日志；不能验证的内容必须明确写出原因，不要把未测内容说成已完成。
- 文档修改完成后必须说明：
  - 修改了哪些文档。
  - 每处主要内容依据来自哪些文件。
  - 发现了哪些文档与代码不一致。
  - 哪些内容无法从当前仓库确认。
