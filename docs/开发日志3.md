# Android 接手备忘

本文件用于快速接手 Android 端开发，不再记录逐日流水细节。权威接口、字段和数据库结构仍以 `backend/schemas.py`、`backend/routers/`、`backend/models.py` 和 `database/init.sql` 为准；发现文档和代码不一致时，先以真实代码为准再同步文档。

## 一、当前定位

- Android 包名：`com.catcafe.app`
- 当前主线：猫咖顾客端闭环，兼有部分 Android 管理端页面代码。
- 业务口径：猫咪本体只用于信息展示、评论和点赞，不作为购买对象；可购买对象是猫咖服务券、餐饮和猫咪用品。
- 金额字段在 Android 使用 `BigDecimal` 或字符串展示，不使用 `float/double` 处理金额。
- 认证和权限以后端 token 为准，Android 不伪造 `userId` 或 `userType`。
- 不随意改数据库结构，不新增未被需求要求的后端接口。

## 二、本机模拟器测试流程

当前 Debug 配置在 `app/build.gradle`：

```text
API_BASE_URL=http://127.0.0.1:8000/
IMAGE_BASE_URL=http://127.0.0.1:8000
```

模拟器里的 `127.0.0.1` 默认指向模拟器自身；本项目通过 `adb reverse tcp:8000 tcp:8000` 把模拟器的 `127.0.0.1:8000` 转发到电脑本机后端。

### 1. 启动 MySQL

管理员 CMD：

```cmd
net start MySQL80
```

如果提示服务已在运行，可以继续下一步。

### 2. 启动后端

新开终端：

```cmd
cd G:\cat-cafe\backend
.venv\Scripts\activate
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

确认电脑浏览器可以打开：

```text
http://127.0.0.1:8000/docs
http://127.0.0.1:8000/api/cats
http://127.0.0.1:8000/api/products
```

### 3. 启动 Android 模拟器

在 Android Studio 打开模拟器，等待系统进入桌面。

可选检查：

```cmd
"D:\Users\yang\AppData\Local\Android\Sdk\platform-tools\adb.exe" devices
```

需要看到类似 `emulator-5554 device`。如果是 `offline`，重启模拟器或 Android Studio 后再试。

### 4. 建立端口转发

通常运行 `installDebug` 会自动执行本项目 Gradle 任务并建立转发：

```cmd
cd G:\cat-cafe\android
.\gradlew.bat installDebug
```

也可以手动执行：

```cmd
"D:\Users\yang\AppData\Local\Android\Sdk\platform-tools\adb.exe" reverse tcp:8000 tcp:8000
```

检查当前转发：

```cmd
"D:\Users\yang\AppData\Local\Android\Sdk\platform-tools\adb.exe" reverse --list
```

应能看到 `tcp:8000 tcp:8000`。如果重启过模拟器，通常需要重新转发或重新运行 `installDebug`。

### 5. 构建与安装

只检查能否编译：

```cmd
cd G:\cat-cafe\android
.\gradlew.bat assembleDebug
```

安装到已启动的模拟器：

```cmd
.\gradlew.bat installDebug
```

Android Studio 运行时确认 Run Configuration 指向当前包名 `com.catcafe.app`，不要使用旧包名 `com.example.catcafe`。

### 6. 主流程手测

测试账号：

| 角色 | 用户名 | 密码 |
|------|--------|------|
| 普通用户 | `user` | `123456` |
| 管理员 | `admin` | `123456` |

建议最小回归流程：

1. 游客打开首页，确认商品、猫咪图片和列表能加载。
2. 进入服务页，确认撸猫券、商品和猫咪列表能加载。
3. 使用 `user / 123456` 登录。
4. 进入商品详情和猫咪详情，测试商品/猫咪点赞、取消点赞。
5. 查看评论列表，测试评论点赞、取消点赞。
6. 发表评论，确认提示等待审核。
7. 加购商品，进入购物车下单。
8. 进入“我的订单”，确认筛选、搜索、详情、编辑和删除能力。
9. 进入“我的点赞”和“我的评论”，确认跳转、取消点赞、删除评论能力。
10. 进入“我的 / 个人资料”，确认用户信息、头像、性别和生日能显示与编辑。

### 7. 真机测试差异

真机不能使用 `127.0.0.1 + adb reverse` 这套模拟器流程。真机同 Wi-Fi 测试时：

1. 后端改用：

```cmd
cd G:\cat-cafe\backend
.venv\Scripts\activate
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

2. Android 的 `app/build.gradle` 中 `BuildConfig.API_BASE_URL` 和 `BuildConfig.IMAGE_BASE_URL` 改为电脑局域网 IP，例如：

```text
http://192.168.x.x:8000/
http://192.168.x.x:8000
```

3. 手机和电脑必须在同一 Wi-Fi，Windows 防火墙需要允许 8000 端口访问。

## 三、已完成功能

### 基础结构

- 底部三入口：`首页 / 服务 / 我的`
- Retrofit / OkHttp / Glide / RecyclerView 基础结构
- `SessionManager` 保存登录态和 token
- `ApiClient` / `ApiService` 统一网络访问
- `NetworkHelper` 收到 401 会清空登录态，并按普通/管理员接口引导重新登录。
- `AppConfig` 统一处理 `API_BASE_URL` 和图片地址
- 公开图片走 `IMAGE_BASE_URL + 相对路径`，后端托管 `/cats`、`/products`、`/avatars`

### 首页与服务页

- 游客可浏览首页、商品列表、猫咪列表。
- 首页推荐优先展示服务类“撸猫券”，再补充其他在售商品。
- 服务页顶部展示“撸猫券”商品入口，下方展示猫咪信息搜索和列表。
- 猫咪列表支持 `includeAll=true` 显示完整猫咪信息。
- 商品业务文案已避免“购买猫咪本体”的误解。

### 登录与个人资料

- 登录、注册、退出登录、登录态保存与 token 校验。
- 普通登录页会拒绝管理员账号进入顾客端操作，提示走管理员入口。
- 登录页已接入“忘记密码”流程：通过 `POST /api/send-sms-code` 获取演示验证码，再调用 `POST /api/reset-password-by-phone` 重置密码。
- 我的页展示头像、用户名、账号类型、用户 ID、手机号。
- 个人资料页支持用户名、手机号、头像路径、性别、生日编辑。
- 我的页已接入“注销账号”入口：调用 `DELETE /api/user/me`，成功后清空本地登录态；后端会删除本人点赞/评论，若存在未支付、制作中、已取消等不可注销订单则拒绝。
- 头像通过 `userAvatar` 加载，支持 `/avatars/...` 相对路径；测试用户 `user` 使用 `/avatars/luoridaqiao.jpg`。

### 商品、猫咪、点赞与评论

- 商品详情页、猫咪详情页已完成。
- 商品详情页、猫咪详情页支持下拉刷新，会重新拉取详情主体和评论列表。
- 商品/猫咪点赞状态展示、点赞、取消点赞。
- 评论列表展示审核通过的评论。
- 商品/猫咪发表评论入口；未登录发表评论时直接跳转登录页。
- 评论本身已支持点赞、取消点赞，使用后端 `likeType=1`，复用 `LikeController`。
- “我的评论”支持查看自己发布过的评论，包含待审核、已通过、已拒绝；支持目标类型筛选、关键字搜索、下拉刷新、跳转目标详情和删除评论。

### 购物车与订单

- 购物车、加购、数量增减、下单前登录拦截。
- 购物车联系人和手机号默认填充当前账号信息，并调用 `GET /api/user/me` 刷新。
- 购物车提交订单前会逐个刷新商品详情，发现下架或库存不足时先提示并调整购物车，不再直接等下单接口兜底报错。
- 下单成功后清空购物车并跳转订单列表。
- 我的订单支持状态筛选、商品名搜索、下拉刷新、订单详情弹窗。
- 待处理订单支持编辑联系人、手机号和备注。
- 已完成或已取消订单支持整批删除。
- Android 顾客端订单更新/删除会遍历 `BatchOrderResponse.items` 中所有 `orderId`，避免只处理 `batchNo` 批次第一条。

### 我的点赞

- “我的点赞”支持查看点赞记录。
- 支持按全部/商品/评论/猫咪筛选，支持关键字搜索和下拉刷新。
- 商品点赞跳商品详情，猫咪点赞跳猫咪详情。
- 评论点赞通过 `targetType + targetId` 跳到原商品或猫咪详情。
- 支持取消点赞。

### Android 管理端现状

- 代码中已有管理员登录入口和部分 Android 管理页：用户、商品、猫咪、评论、订单。
- 商品管理、猫咪管理的新增/编辑弹窗已支持本地选择图片并上传：商品走 `POST /api/admin/upload` + `type=product` 回填 `imageUrl`，猫咪走 `type=cat` 回填 `photoUrl`；仍保留手填 URL 或相对路径能力。
- Android 管理端订单页已按 `BatchOrderResponse.items` 遍历所有 `orderId` 更新/删除。
- 管理员功能仍建议优先以 Web 后台为主，Android 后续只按明确需求补。

## 四、当前问题与缺口

### Android 侧待办

当前 Android 优先级待办已处理完毕；后续按新需求继续补充。

### 项目级风险

1. Web 管理端订单页 `web/cat-cafe-ui/src/views/adminOrders.vue` 仍使用 `row.items[0].orderId` 更新/删除订单；页面看似操作整批，实际可能只改 `batchNo` 批次第一条。Android 端已规避，Web 端未修。
2. 后端下单库存扣减是先查库存再扣减后提交，缺少行锁或乐观并发控制；高并发下存在超卖风险。
3. 售后服务范围未定义：订单问题反馈、取消/退款申请、客服留言，还是仅订单备注。未定义前不要新增表、接口或复杂页面。

## 八、常见排查

- App 一直转圈、登录无响应或 10 秒超时：优先检查后端是否运行、数据库是否可连接、`adb reverse --list` 是否存在 `tcp:8000 tcp:8000`。
- 模拟器历史上访问 `10.0.2.2:8000` 曾超时；当前 Debug 使用 `127.0.0.1 + adb reverse`。
- Android Studio 启动失败并提示找不到 Activity：检查 Run Configuration 是否残留旧包名 `com.example.catcafe`。
- 图片不显示：先在电脑浏览器确认 `http://127.0.0.1:8000/cats`、`/products`、`/avatars` 对应静态路径由后端托管。
- 管理员账号不能走普通顾客操作；普通登录页会提示使用管理员入口。
